We introduce the concept of Declarative Data Groups (DDGroup). A DDGroup defines the way instances can be assigned to groups given a set of conditions. For example, experimental observations can be grouped by type of sensor or area. This novel concept empowers the declaration of various types of groups. Group declarations are stored alongside the data and invoked via a query. This notion of groups permits to execute aggregate functions concerning the members belonging to a declared group.

Introduction

The Shape Constraint Language (SHACL), a W3C recommendation, in their advanced features (SHACL-AF) enable to describe derived values using SHACL-SPARQL and Node rules. However, at present, there is a lack of a standard to describe dynamic groups and aggregate calculations of that groups. DDGroups built on top of SHACL-AF and offer multiple constructors in RDF to declare groups and also calculations about that groups. In a context of heterogenous and incomplete data, DDGroups are suitable to leverage semantic and contextual data. Besides, aggregate functions can be adapted to a particular knowledge model such as the standard ontology SOSA.

DDGroups

Main class inspired in sh:NodeShape, with a different semantic of groups

          ex:obsDDG rdf:type sh:NodeShape, ddg:DDGroup.

ddg:TargetClass

The initial group of elements, for instance all the instances of the class observation. DDGroups can only have one target class and it is mandatory. 

          ex:obsDDG ddg:targetClass  sosa:Observation.

ddg:TargetExpression

Related to the ddg:TargetClass, it permits to add a pattern to the given class. For instance, observations about temperature. DDGroups can have multiple target expressions 

          ex:obsDDG ddg:targetExpression [
            sosa:observedProperty ex:PAR ; ## added to the target class
          ];

Grouping Conditions

DDGroups can have one or several Grouping Conditions (GC). A GC is compounded of two main elements a Path and a Node. The node can be a constant or a Variable. If the Node is a Variable thus this declaration is going to produce one group for each different value on the data. 

        ex:obsDDG ddg:groupingCondition [
          ddg:path sosa:resultTime;
          ddg:var "?dateNoTime";
          ddg:map xsd:date # transform the value obtained from the path, xsd:gMonthDay is a ARQ jena function already loaded
        ];

ddg:path

GCs often refer to a node reachable from the current focus node, the path indicates how to navigate to that node. A path can be an URI node about a RDF property, or a literal with a nested Path. For instance, "sosa:hasResult/qudt:numericValue/". We refer to this obtained node as the local node to distinguish from the focus node.

ddg:var

A variable enables to identify the GC when invoked in a query.

ddg:map

Map functions are suitable to apply transformations to the local node. For instance, transform a time date to a date.

DDGroup filters

DDGroup filters are associated to Grouping Conditions (GC), the path in a GC enable to access to a local node. A filter facilitate the comparison between the focus and local node properties. For instance, observations collected in a period interval related to an experiment. 

        ddg:groupingCondition  [
          ddg:path "sosa:hasFeatureOfInterest/^ex:sownIn/ex:participatesIn";
          ddg:var "?exp";
          ddg:filter [
                  ddg:localPath ex:initialDate;
                  ddg:cond ddg:lessThan;
                  ddg:path sosa:resultTime;] ;
          ddg:filter [
                ddg:localPath ex:endDate;
                ddg:cond ddg:greaterThan;
                ddg:path sosa:resultTime;]
        ];

ddg:localPath

Path from the local node.

ddg:cond

Filter condition, e.g., less than, equal, greather than.

ddg:path

Path from the focus node.

Mathematical SHACL Rules (sh-math:NodeRule)

The previous constructors facilitate the declaration of groups, in this section we detail particular rules to apply aggregate functions to the groups, the rule take into account that the group contain elemnts with numerical values. 

        sh:rule [
          a sh-math:NodeRule ;
          sh:path ex:avgTemp;
          sh:datatype xsd:integer  ;
          sh:values [
            agg-sosa:avg(sh:this ex:Temperature  unit:DEG_C  )
          ];
          sh:order 2;
        ];

Query-Answerinng for DDGroups

a DDGroup declaration can have multiple node rules, each rule enable an aggregate calculation considering memebers of a group. This DDGroup can be access from a SPARQL query and particular node rules can be invoked. The system will only compute that rule, althougt the system can have various rules.
